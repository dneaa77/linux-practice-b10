# Практическая работа №10 — Страничная адресация и TLB (Ubuntu)

Проект: три отдельных варианта, один README, общие `results/` и `screenshots/`.

**Важно:** преподавательские `translate.py` и `refs.txt` не предоставлены. Здесь самостоятельная реализация и **демонстрационный** `refs.txt`. Принят PAGE_SIZE=1024 байта, так как в условии размер страницы не указан. Перед сдачей заменить исходные данные на преподавательские при необходимости.

## Подготовка Ubuntu

```bash
sudo apt update
sudo apt install -y python3 python3-matplotlib build-essential linux-perf libcap2-bin
cd practice10
```

Если `linux-perf` недоступен, проверь `apt search linux-tools` и установи подходящий для своего ядра пакет. `perf` может быть запрещён настройкой `kernel.perf_event_paranoid` даже при установленном пакете.

## Вариант A — адресация

`python3 variant_a/translate.py | tee results/variant_a.txt`

Таблица страниц: 0→5, 1→2, 2→7, 3→0. Размер страницы: 1024 байта.

- 1200 = 1×1024 + 176. Страница 1, смещение 176, кадр 2. Физический адрес = 2×1024+176 = **2224**.
- 3100 = 3×1024 + 28. Страница 3, смещение 28, кадр 0. Физический адрес = 0×1024+28 = **28**.
- 5000 = 4×1024 + 904. Страница 4 отсутствует в таблице → **страница отсутствует**.

Размер страницы выбирают степенью двойки, чтобы извлекать смещение младшими битами адреса, а номер страницы — сдвигом вправо, без обычного деления и остатка.

## Вариант B — TLB LRU

`python3 variant_b/main.py | tee results/variant_b.txt`

Создаёт `results/tlb_trace.csv`, `results/tlb_sizes.csv`, `results/tlb_hit_rate.png`.

В демонстрационной модели TLB=10 нс, память=100 нс. Для одноуровневой таблицы:

- попадание: 10 + 100 = 110 нс;
- промах: 10 + 100 (таблица) + 100 (данные) = 210 нс;
- EAT = h×110 + (1−h)×210 нс.

Промахи из-за отсутствующей страницы не учитываются при подсчёте TLB hit rate, потому что требуют отдельной модели page fault.

Двухуровневая таблица без TLB: 2 обращения для таблиц + 1 для данных = **3 обращения**. С TLB hit — 1 обращение к данным, miss — 3 обращения (плюс проверка TLB).

## Вариант C — реальные страницы

```bash
python3 variant_c/pagemap.py | tee results/pagemap.txt
python3 variant_c/shared_mmap.py | tee results/shared_mmap.txt
gcc -O2 -Wall -Wextra -std=c11 variant_c/tlb_benchmark.c -o variant_c/tlb_benchmark
./variant_c/tlb_benchmark | tee results/tlb_benchmark.txt
./variant_c/tlb_benchmark --huge | tee results/tlb_benchmark_huge.txt
perf stat -e dTLB-load-misses ./variant_c/tlb_benchmark 2> results/perf.txt
```

`/proc/self/pagemap` часто скрывает PFN без CAP_SYS_ADMIN. **Root сам по себе не гарантирует CAP_SYS_ADMIN** (например, в контейнере). Если PFN=0, нельзя утверждать, что физический кадр найден.

`shared_mmap.py` демонстрирует общий файл и видимость изменений между процессами; **не доказывает совпадение PFN**, если PFN скрыты. Виртуальные адреса могут совпасть случайно, поскольку процессы имеют независимые адресные пространства. Для строгого доказательства одного кадра нужен разрешённый доступ к pagemap обоих процессов.

`perf stat` может вернуть `Permission denied` или `event syntax error`: проверь `perf --version`, права доступа и поддержку события процессором. Не выдавай отсутствующие измерения за успешные.

`MADV_HUGEPAGE` — лишь рекомендация ядру. Реальное применение huge pages нужно проверять по `/proc/<pid>/smaps` (например, `AnonHugePages`) во время работы процесса; на коротком тесте эффект может не проявиться.

Сравни время для шагов 64 байта и размер страницы. Время зависит не только от TLB, но и от кэшей, предвыборки и числа обращений; **наивное сравнение разных шагов не изолирует TLB**. Используй perf и повторные прогоны для обоснованного вывода.
